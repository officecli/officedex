# PPTX 失败后显示绘制完成：修复记录

## 复现

任务 `01a08fdd-d0c8-7722-863b-f8dd1001e124` 的扩写阶段仅完成第 2、7 页，后端发送 `deck.begin` 后 `run.failed`。旧界面把任何绘制操作视为打开编辑器的条件，并把失败终态当作 completed，消费完队列后显示 done，留下空白草稿。

## 本次修改

- buildReplayFeed 明确传递运行、成功、失败、取消及后端错误。completed 仅保留为流是否关闭的兼容字段，不再代表成功。
- 绘制器在保存已有部分内容后保留失败/取消终态。没有页面时不保存空白生成结果。
- 明确成功的任务还需存在实际绘制内容、所有预期页码的 slide.end，以及保存成功，才能显示 done。
- 自动打开编辑器需要 shape.add 或 diagram.add；deck.begin / slide.begin 不触发。异步创建草稿期间任务若结束或用户已打开文件，不再自动切换。
- 可重试传输错误使用单次请求预算，只有 JSON/内容修复使用 repair 预算。超时与结果不明的网络错误沿用工作区已有的不自动重发策略。

## 与工作区已有功能的衔接

已验证逐页正文预览、失败页状态和显式检查点续作。正文不依赖前序页完成；续作创建新任务、新输出，仅对未完成页请求模型，重用成功正文和匹配的已保存图片。

最终绘制仍按页序；这里交付的是独立正文预览，不是乱序完成的最终版式缩略图。指定页乱序绘制涉及 worker 协议和编辑器页 ID，尚未在本次实现。
