OfficeDex 七轮问题复审与修复

覆盖 1.0.15、1.0.18、1.0.19、1.0.20、1.0.21、1.0.22、1.0.23。五种新增格式按用户确认另做。

反复出现的核心原因是完成契约和回归范围不完整：曾把生成副本当作保存原件，把页数正确当作内容正确，把单个入口成功当作整类问题关闭。异步任务、引用正文、iframe 焦点和旧断点分别暴露了未覆盖路径，并非每次都是同一补丁被回退。

本页区分源码回归与原生验收。下列代码修复和自动化证据不能冒充签名客户端已全量复测。本轮未发布新版本，也未将未知错误写成“已定位”。

本轮新增修复

  • Apply 带修改开始时的原件 SHA-256；写入前校验冲突及权限，保留文件模式。Undo 只允许原目标且没有后续编辑。
  • 每个修改任务使用独立提案路径，后续任务不会覆盖待审阅副本；部分操作失败或需要注意的结果不再标为成功。
  • 修复 DOCX 空段落造成的索引偏移、相同段落误替换、替换导致格式丢失。中英文精确替换且要求其他内容不变时直接修改原 XML，目标不存在或不唯一时拒绝猜测，并保留 Word 对首尾空白的语义。
  • 只读问答读取真实文件文本并返回答案，拒绝任何写操作；“仅输出副本”不自动写回原件。引用正文和文件名中的权限词不改变路由。
  • 补齐 Review 目标文件名换行样式，扩大发布前门禁到全部前端、Go 文件操作、真实转换器和恢复链路。

npm run lint && npm run test:acceptance:regressions 已完整通过，退出码 0。最终补充的文件名路由及 DOCX 空白语义修正也重新通过 lint、全量前端和受影响 Go 测试。

验证层实际结果
前端与桥接149 个测试文件，1,616 项全部通过；真实生成的 Wails 绑定携带原件 SHA-256。
浏览器与样式7 项通过，无跳过；实际 Chromium 中 iframe 标题／备注按键与重载、样式构建检查。
Go 文件操作主包与 internal 源码包通过；真实 DOCX 原件写回及 Undo 哈希恢复，外部冲突、只读权限、目标错误、权限保留均覆盖。

完整门禁不会遍历 dist-artifacts 中的历史源码归档，避免其作为本模块包被误编译。所有检查均为本地代码或有限时长的测试，没有启动未经 devctl 管理的开发实例。

关闭边界

  • 1.0.23 两次 Review “Couldn’t finish”未附底层错误详情。已用报告原始中文请求加入精确替换回归，但这不能证明历史失败根因相同，仍需原生重跑取得任务 ID 和错误。
