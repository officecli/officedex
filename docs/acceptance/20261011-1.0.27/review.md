# QA26 / N26-01：打开文件重命名后的保存

报告：`OfficeDex-1.0.26-问题走查报告-20261011.html`，确认一个跨 DOCX/PPTX/XLSX 的 P1 问题。只修已有格式；仍发布 macOS ARM Test。

## 根因及此前为何漏检

RenameDocument 只移动磁盘文件并更新数据库。文档 ID 虽然稳定，打开中的预览 token、PPTX/XLSX 编辑会话和来源指纹表仍保留旧路径。此前的重命名测试只验证 ID/名称/磁盘移动，保存测试只验证未改名的会话，两条路径没有交叉。QA24 的字体、前台绘制和严格生成修复与此缺陷独立；没有证据说明是 1.0.26 引入的回归。

新增测试先在修复前重现报告的全部三种错误：DOCX 旧路径不存在、PPTX token/session mismatch、XLSX 旧路径 lstat 失败。

## 修复

- 重命名保留 token、会话 ID、工作副本、修订号和未保存修改，迁移预览授权、编辑会话保存目标及来源指纹。
- 用读写锁隔离重命名和进行中的准备/读取/保存操作，避免一次保存跨越两个路径；不同文档的常规读取、准备、保存仍可并行。
- 原路径在文件移动前解析，目标在移动后解析，兼容 macOS 路径别名及符号链接。
- 数据库迁移失败时恢复磁盘原名。重名失败不改变会话。迁移保留冲突基线，不把外部修改当作本次保存的合法来源。
- 没有通过销毁、重新导入编辑器来修复，因此未保存内容及 PPTX 工作快照继续保留。

## 回归与发布门禁

Go 集成测试使用真实预览注册表和真实编辑会话，覆盖三格式连续重命名两次后保存/重试、正在保存时改名、磁盘与数据库回滚、外部修改保护、外部选中文件的精确授权迁移。并发测试用 race detector 执行。

浏览器测试用报告原始附件、真实 Go bridge、真实编辑器和转换器：菜单 Rename → 编辑 → 保存；模拟一次保存通道故障 → 未保存状态再次 Rename → Retry；解包新路径的 OOXML 验证正文、备注、B2 数值及 B4 的 SUM 公式；同时断言原路径未重建、token/session 未更换。

Word、PPTX 在 Playwright WebKit 运行。此环境的 Sheet SDK 在重命名前启动即产生无堆栈 TypeError，所以 XLSX 在 Chromium 验证，并要求发布前检查最终包的原生 WKWebView。该差异不作为原生 XLSX 已通过的替代证据。Word/PPTX 前台绘制与字体资源门禁继续保留，新增重命名测试纳入完整 macOS 构建。

本地 `dist-artifacts/test-1.0.27/verification.json` 保存最终来源提交、测试证据、原生核验、签名公证、资产 SHA-256 和远端 Test 清单核验结果。
