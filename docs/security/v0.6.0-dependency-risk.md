# OfficeDex v0.6.0 dependency risk acceptance

Audit date: 2026-07-16

OfficeDex `v0.6.0` applies the available non-breaking npm updates, including
Vite `6.4.3`, Vitest `3.2.7`, and `npm audit fix` without `--force`. The release
does not take major preview-library migrations that could change document
rendering immediately before publication.

## Root application production audit

`npm audit --omit=dev` reports four high-severity dependency entries. They map
to two direct preview libraries and one optional Node-only dependency chain:

| Dependency | Advisory | OfficeDex runtime path | v0.6.0 decision |
| --- | --- | --- | --- |
| `pdfjs-dist@3.11.174` | [GHSA-wgrm-67xf-hhpq](https://github.com/advisories/GHSA-wgrm-67xf-hhpq) | `src/renderer/preview/viewers/PdfViewer.tsx` parses and renders PDF bytes selected through an OfficeDex preview token. | Accepted for `v0.6.0`. The registry fix is `pdfjs-dist@6.1.200`, a breaking major upgrade requiring worker/import/rendering migration and focused malicious-PDF regression coverage. |
| `xlsx@0.18.5` | [GHSA-4r6h-8v6p-xvw6](https://github.com/advisories/GHSA-4r6h-8v6p-xvw6), [GHSA-5pgg-2g8v-p4x9](https://github.com/advisories/GHSA-5pgg-2g8v-p4x9) | `src/renderer/preview/viewers/XlsxViewer.tsx` parses workbook bytes and converts the selected sheet to HTML. | Accepted for `v0.6.0`. npm has no fixed registry release; replacement or use of the vendor distribution must be evaluated as a separate preview-library migration. |
| `@mapbox/node-pre-gyp` / `tar` | Multiple `node-tar` path traversal advisories reported through `pdfjs-dist`'s optional `canvas` package | Optional Node canvas installation/tooling path. OfficeDex's renderer uses the browser PDF.js worker and a DOM canvas; the native optional package is not imported by product code or bundled by Vite. | Accepted as inherited optional metadata for `v0.6.0`; remove by the same PDF.js major migration rather than adding an unused native canvas override. |

The accepted risk is limited to opening untrusted PDF/XLSX content inside the
local preview surface. Users should use the external viewer action for
untrusted documents until the preview migrations land.

## Vendored PPTist audit

The vendored PPTist lockfile received `npm audit fix` without `--force` and was
then rebuilt, type-checked, and tested. `npm audit --omit=dev` reports zero
production vulnerabilities. The remaining full-audit findings are confined to
build/development tooling (`esbuild` through Vite 5 and `minimatch` through the
legacy ESLint stack); `third_party/pptist/node_modules` is excluded from source
control and release packages.

## Required follow-up

1. Migrate PDF preview to PDF.js 6 with worker packaging, malformed-document,
   and desktop bundle tests.
2. Replace or upgrade SheetJS and add hostile workbook/HTML sanitization tests.
3. Upgrade the vendored PPTist build toolchain separately (Vite and ESLint) to
   clear development-only advisories without destabilizing the embedded app.
